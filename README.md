# Сопоставление складской номенклатуры с каталогом запчастей

Небольшой пример под задачу из вакансии AI-аналитика AgroStock: взять «грязный» складской список агропредприятия,
сопоставить его с единым каталогом запчастей, найти дубли и отделить то, что не является запчастями.

Сделано мной с помощью Claude Code (ИИ-ассистент для программирования): я ставил задачу, проверял результат
и правил логику, ИИ помогал писать код.

## Что на входе

Данные вымышленные: реальных данных компании у меня нет. Но ошибки в них такие, как в настоящих складских таблицах.

- `data/catalog.xlsx` — каталог: 448 позиций (15 моделей техники: МТЗ, К-700, John Deere, Claas, Енисей и др.).
- `data/client_stock.xlsx` — склад клиента: 488 строк. В них:
  - сокращения: «Ф-р масл.», «Подш.», «т/о»;
  - разная запись моделей: «МТЗ-80», «мтз80», «мтз 80»;
  - опечатки: «Енсией-1200», «Claas Tucnao»;
  - артикулы без дефисов, с «арт.», с опечаткой в цифре или вообще без артикула;
  - одна и та же запчасть, заведённая дважды;
  - не запчасти: перчатки, солидол, антифриз.

## Как работает (`match.py`)

1. **Артикул.** Привожу к одному виду (без пробелов, дефисов, «арт.») и ищу точное совпадение.
   Если артикул совпал, а название совсем другое, не верю и отправляю на ручную проверку.
2. **Название.** Раскрываю сокращения, выравниваю запись моделей и ищу самые похожие позиции нечётким
   сравнением, которое терпит опечатки и другой порядок слов.
3. **Артикул с опечаткой в одной цифре** плюс совпавшее название тоже считаю совпадением.
4. **Уверенность** у каждой строки:
   - «Точно» — совпал артикул;
   - «Вероятно» — совпало название или артикул с опечаткой;
   - «Проверить вручную» — показываю 3 лучших кандидата, когда система сомневается
     (например, «насос водяной мтз-82» похож и на МТЗ-82, и на МТЗ-80);
   - «Не найдено» — позиции нет в каталоге запчастей.
5. **Дубли** — строки склада, которые указывают на одну позицию каталога. Их остатки складываются.

## Результат: `result/matching_result.xlsx`

| Показатель | Значение |
|---|---|
| Строк на складе | 488 |
| Сопоставлено автоматически («Точно» + «Вероятно») | 426 |
| На ручную проверку | 2 |
| Не найдено (не запчасти) | 60 |
| Найдено дублей | 47 позиций каталога |

**Проверка точности** (`check_accuracy.py`): для тестовых данных правильный ответ известен заранее
(`data/truth.csv`). Все 426 автоматических сопоставлений верные, все 47 дублей найдены,
все 60 «не найдено» действительно не запчасти.

На реальных данных точность будет ниже: ошибки там разнообразнее. Поэтому система не угадывает,
а при сомнении отправляет строку человеку. Пороги уверенности настраиваются в начале `match.py`.

## Что можно добавить на реальной работе

- Шаг с ИИ-моделью для строк «Проверить вручную»: модель выбирает кандидата и объясняет почему,
  человек только подтверждает.
- Справочник сокращений и синонимов, который пополняется по мере работы.
- Выгрузку проверенных данных в формат для загрузки в систему.

```
.venv/bin/python match.py           # сопоставление -> result/
.venv/bin/python check_accuracy.py  # проверка точности
```
